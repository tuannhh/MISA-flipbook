# HF-20260921-04 — Candidate Docker public edge

## Scope included

- Docker Compose exposes only the Nginx proxy at port 8080. API and Next.js web services have
  no host port; browser API calls use same-origin `/api`. PostgreSQL and Redis remain loopback-only
  for local diagnostics; conversion services remain internal.
- The Nginx image runs as the unprivileged `nginx` user, drops Linux capabilities, disallows new
  privileges and is healthchecked through IPv4. It keeps upload streaming unbuffered, applies a
  201 MB request limit, does not add an independent cache, and preserves API cache policy.
- The proxy overwrites client-provided `X-Forwarded-For`. API enables Express `trust proxy` only
  for a validated `TRUST_PROXY_HOPS` value; Docker pilot has exactly one trusted hop. The public
  edge adds `X-Content-Type-Options`, a minimal Permissions-Policy and a Referrer-Policy that
  prevents reader query grants from being sent to cross-origin PDF hyperlinks.
- CI executes all HTTP E2E suites through `/api` at the public proxy and includes a proxy
  regression that proves a forged XFF header cannot evade the login limiter.

## Compatibility and rollout

1. Existing local `infra/docker/.env` must set `WEB_PUBLIC_API_BASE_URL=/api`,
   `CORS_ORIGIN=http://localhost:8080` and `TRUST_PROXY_HOPS=1`. The checked-in `.env.example`
   has these defaults; the local ignored `.env` used for this verification was migrated.
2. Do not expose API or web ports separately while `TRUST_PROXY_HOPS=1`. A direct API deployment
   must set it to `0`.
3. The bundled proxy is HTTP-only for local Docker. At MISA, DevOps must terminate TLS and document
   the full proxy/load-balancer chain. Set the exact trust hop count or an approved proxy allowlist;
   never assume one hop after an external gateway/CDN is added.
4. This change is additive at schema level and needs no migration. It is compatible with migration
   head `0020_storage_accounting.sql` and PDF pipeline `v1`.

The proxy initially failed a cold start because Nginx non-root could not write its default PID path;
the image now uses `/tmp/nginx.pid`. A subsequent healthcheck false negative came from BusyBox resolving
`localhost` to IPv6 while the minimal config listens on IPv4; it now probes `127.0.0.1`. Both fixes
were verified by a clean container recreation ending in `healthy`.

## Known limits before stable

- The one-hop XFF test does not validate the final MISA TLS/CDN/load-balancer topology, trusted
  upstream network policy or a production WAF. Those are DevOps acceptance items.
- No HTTPS certificate, CDN cache-purge test, object storage lifecycle/HA test, production backup
  restore drill or long soak test has been performed.
- Responsive behavior still needs the agreed physical-device matrix. PDF audio/video remains
  deliberately deferred until real MISA samples and media policy are provided.
- GitHub Actions steps are committed, but no hosted Actions run was observed in this local task.
