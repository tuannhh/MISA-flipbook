# HF-20260921-07 — Candidate supplement: Admin creates flipbooks

**Status:** candidate, not stable. This supersedes the runtime reference in HF-20260921-06.

**Runtime source revision:** `493835dff0b5500b01ebba1ddfa4ee8cf6218c86` on
`codex/pdf-pipeline-hardening`.

## Corrected behavior

The simplified Admin dashboard had retained cross-tenant view/edit/delete but accidentally removed
its create-book entry point. A System Admin can now choose an active tenant, enter a flipbook title,
and create a draft owned by the current Admin. The browser then opens the book detail page with the
selected tenant context, ready for PDF upload. This preserves tenant isolation: the API still verifies
Admin status and routes the create request through the existing tenant/RLS transaction; no client-side
owner or tenant claim is trusted.

The Admin screen now has a desktop **Tạo flipbook** action and a mobile create button. The action is
disabled only when no active tenant exists, with an explanatory dialog state. The selected tenant is
loaded from the Admin-only endpoint and suspended tenants are excluded.

## Verification

- Next.js production build passed.
- The isolated Docker candidate at `http://127.0.0.1:13000` was rebuilt and returned `/admin` HTTP 200.
