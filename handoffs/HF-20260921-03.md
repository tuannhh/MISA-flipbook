# HF-20260921-03 — Candidate storage accounting and resilient rate limiting

**Status:** candidate, not stable. No tag has been created.

**Runtime source revision:** `00e3af4ad3147ae913d6f0a79b4565dee0eb599c` on
`codex/pdf-pipeline-hardening`, following candidates `d000b18` and `609435e`.

## Scope included

- Migration `0020_storage_accounting.sql` adds tenant logical/physical storage accounting
  and maintenance-run evidence. Upload admission checks source and total logical quota; worker
  serializes derived-asset quota decisions by tenant and fails safely before inserting asset rows.
- Local-volume reconciliation runs on worker start and at a configured interval. It removes only
  retention-expired, unreferenced temporary upload, thumbnail-source, share-thumbnail and render
  attempt folders. It does not follow symlinks or remove source PDF files after an ambiguous
  database outcome.
- Login and book-password limiting use a shared Redis authority with a short command deadline,
  bounded in-process fallback during Redis outage, and source-wide caps against password spraying.
  Redis/fallback keys HMAC source addresses and emails; `RATE_LIMIT_KEY_SECRET` should be stored
  separately from `JWT_SECRET` in production.
- CI runs new storage and Redis-down regression suites. The worker also closes its maintenance
  pool cleanly during shutdown.

## Compatibility and rollout

1. Deploy API and worker-convert together with migration `0020`; retain the previously required
   coordinated deployment of dispatcher/worker-convert from `d000b18`.
2. Set `TENANT_STORAGE_BYTES`, `STORAGE_ORPHAN_RETENTION_SECONDS` and
   `STORAGE_RECONCILE_INTERVAL_MS` to the approved tenant policy. Default quota is 50 GiB and
   default retention is 24 hours.
3. Set a dedicated `RATE_LIMIT_KEY_SECRET`. If omitted, the Docker-pilot fallback is `JWT_SECRET`.
   Raw legacy rate-limit keys made by earlier code naturally expire within their existing
   15-minute window; do not flush production Redis merely to remove them.
4. Monitor `storage_reconciliation_runs`, `tenant_storage_usage.unattributed_bytes`, failed jobs
   with the quota error, and the redacted Redis-fallback warning. Alert thresholds belong to the
   MISA DevOps runbook.

Migration 0020 is additive except for replacing the narrowly scoped `upload_tenant_budget(uuid)`
function with a compatible result that adds `logical_bytes`. Earlier API code reads named fields it
already uses and remains schema-compatible, but older worker code would not enforce the derived
asset quota. Do not roll back only worker code while continuing to accept uploads if that quota is
required.

only outage log was one redacted fallback warning. A clean Redis scan after a failed login showed
HMAC key components rather than raw email/IP values.

## Known limits before stable

- Responsive behavior has build and integration coverage, but no certification on the agreed old
  phones, current phones and tablets.
- PDF audio/video remains deliberately deferred until a real MISA PDF sample and media policy are
  available; PDF JavaScript, Launch, Flash and arbitrary actions remain unsupported.
- CDN purge/cache behavior and `trust proxy` must be validated against the eventual MISA proxy
  topology. Object storage lifecycle, HA and a long kill/restart soak are also not yet production
  evidence.
- Docker CI steps are committed but no GitHub Actions run was observed from this local task.
