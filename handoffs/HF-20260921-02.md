# HF-20260921-02 — Candidate reader, PDF safety and operations

**Status:** candidate, not stable.

**Baseline:** `745e28c` (Claude audit response) + `d000b18` (Codex pipeline hardening).
**Candidate revision:** the Git commit containing this file.

## What this candidate fixes

- Replaces full Dashboard JWTs in reader asset/download URLs with a short-lived reader
  token scoped to one book and one revision. A password or visibility change invalidates
  reader tokens immediately; an active owner session is rechecked against its membership.
- Pins an active reader to the revision it opened, so publishing a replacement PDF does not
  break page images mid-session. Analytics events have a signed session ID and a database
  uniqueness guard, so retries and server-rendered metadata do not inflate counts.
- Makes protected reader responses `private, no-store`, and public reader responses
  `public, max-age=0, must-revalidate` so a previous public cache entry cannot survive a
  later Password/Private setting.
- Corrects PDF annotation rectangles for CropBox and /Rotate and rejects unsafe URI actions.
- Adds a safe 8 MB PNG/JPEG/WebP social-cover upload that the isolated PDF worker converts to
  an exact 1200×675 WebP. Public OG metadata uses the selected cover. Protected books expose
  no title or preview image to crawlers.
- Establishes `/<slug>-<8char>` and `/embed` as canonical reader URLs, retaining legacy
  `/read/...` routes. Reader downloads images around the viewport, has a page navigator,
  single-page touch mode and keyboard/dialog accessibility fixes.
- Replaces Admin book list client-side filtering over 500 rows with server keyset pagination.
- Adds pilot-only backup/restore scripts with `--quiesce`, a SHA-256 manifest and a destructive
  restore guard.

## Deployment requirements

1. Deploy API, web, dispatcher, worker-convert and pdf-worker together; do not mix this
   reader/pipeline protocol with an older worker image.
2. Apply migrations `0017_reader_sessions.sql`, `0018_share_thumbnail.sql` and
   `0019_admin_books_cursor.sql` after the already-required `0015`/`0016` migrations.
3. Configure `PDF_WORKER_URL` and `INTERNAL_API_TOKEN` for the API. Keep PDF worker internal.
   Configure the thumbnail/upload limits only if the production policy differs from defaults.
4. Purge existing public-reader CDN caches once at rollout. Existing browser/CDN entries made
   under the old `immutable` rule cannot be recalled by application code.
5. Test the backup and restore scripts in a separately provisioned staging environment before
   scheduling them for production.

## Known limits and next work

- A reader token is still carried in an asset query string for `<img>` compatibility. It is
  scoped, short-lived, has `Referrer-Policy: no-referrer`, and cannot authenticate Dashboard
  endpoints. Move to signed cookies or same-origin proxy only if a future production threat
  model requires query-free protected media.
- Test the responsive reader on actual supported phones/tablets; current validation is build
  and integration coverage, not a device certification for this candidate.
- Audio/video embedded in production PDFs still needs real samples and a defined safe media
  policy. Direct Instagram publishing remains platform-account dependent.
- Add derived-storage accounting, orphan-attempt retention and a production object-storage
  adapter before HA deployment. Validate `trust proxy` only when the production proxy topology
  is fixed.

## Rollback

The three migrations are additive: reader helper functions/table, a new allowed asset kind, and
an index. Rolling code back to `d000b18` is schema-compatible after smoke testing; it loses the
new reader/session and cover behavior but preserves books and revisions. Do not restore a
database backup merely to roll back code. If a data restore is ever needed, follow
`HANDOFF.md`, first restore to staging, and obtain explicit approval because newer uploads may
be lost.

When the user explicitly accepts this candidate, add an annotated stable tag to its commit and
record the resulting image digests and backup reference here. Do not move a stable tag.
