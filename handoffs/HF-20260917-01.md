## Runbook
- Lệnh triển khai đã kiểm chứng (Docker Compose dev, KHÔNG phải staging/production thật):
  ```bash
  cd infra/docker
  docker compose build <service>   # bắt buộc trước up cho service build-from-source
                                     # (migrate/api/web/pdf-worker/dispatcher/worker-convert)
  docker compose up -d <service>
  docker compose ps                 # xác nhận "healthy"
  ```
- Lệnh backup/restore đã kiểm chứng thật (xem chi tiết đầy đủ + các bẫy Windows/Git Bash trong
  MEMORYBANK.md mục "P5"):
  ```bash
  # Backup DB (chạy trong container postgres đang sống):
  export MSYS_NO_PATHCONV=1   # bat buoc tren Windows/Git Bash, tranh path bi doi sai
  docker compose exec -T postgres pg_dump -U misa_admin -Fc -d misa_flipbook -f /tmp/backup.dump
  docker cp misa-flipbook-postgres-1:/tmp/backup.dump "<duong-dan-Windows-that>/backup.dump"

  # Backup storage (volume Docker) qua container alpine dung 1 lan:
  docker run --rm -v misa-flipbook_storage_data:/data -v "<thu-muc-dich>:/backup" \
    alpine tar czf /backup/storage_backup.tar.gz -C /data .

  # Restore thu (moi truong tach biet, KHONG dung DB/volume dev dang chay):
  docker run -d --name <ten-container-tam> -e POSTGRES_USER=misa_admin \
    -e POSTGRES_PASSWORD=<mat-khau> -e POSTGRES_DB=misa_flipbook -p 15433:5432 postgres:16.4
  export MSYS_NO_PATHCONV=1
  docker cp "<duong-dan-Windows-that>/backup.dump" <ten-container-tam>:/tmp/backup.dump
  docker exec <ten-container-tam> pg_restore -U misa_admin -d misa_flipbook --no-owner \
    --role=misa_admin -v /tmp/backup.dump
  # Loi "role app_user does not exist" tren cau GRANT la BINH THUONG (role la cap cluster,
  # pg_dump 1 DB khong mang theo role) - khong anh huong du lieu/schema.
  docker exec <ten-container-tam> psql -U misa_admin -d misa_flipbook -c \
    "SELECT count(*) AS books, (SELECT count(*) FROM tenants) AS tenants, (SELECT count(*) FROM assets) AS assets FROM books;"
  # Doi chieu voi baseline da chup truoc backup. Xong thi don:
  docker rm -f <ten-container-tam>
  ```
- Smoke tests sau chuyển traffic: chạy đủ 6 bộ test trong `tests/integration/` (xem danh sách
  ở mục "Test suite" bên trên) + đăng nhập thật qua trình duyệt (admin + creator), mở 1 sách
  công khai, publish thử 1 revision.
- Owner vận hành / vị trí log: `docker compose logs -f <service>`; chưa có log tập trung
  (ELK/Cloud Logging) — việc này thuộc phạm vi khi thật sự chuyển sang staging/production.
- Điều kiện dừng và phương án khắc phục: nếu `docker compose ps` báo service không "healthy"
  sau khi `up`, kiểm tra `docker compose logs <service>`; đa số lỗi trong phiên này bắt nguồn từ
  quên `docker compose build` trước `up` cho service build-from-source (không có volume mount
  code sống).
